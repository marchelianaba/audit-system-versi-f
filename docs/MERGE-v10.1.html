1Situasi & Tantangan

v10.1 adalah satu commit tunggal (c3da1e2 "Initial commit", 27 Jul) hasil squash — tidak memiliki riwayat git bersama dengan repositori ini. Akibatnya git merge biasa mustahil (unrelated histories), sehingga penggabungan harus dilakukan file per file.

Kedua lini bercabang, bukan satu lebih maju

v10.1 bercabang dari lini kerja ini sekitar 19–22 Juli. Artinya:

  • v10.1 sudah memuat sebagian pekerjaan saya (penilaian per-aspek, pelindung sel-gabung LKE, mode limit langganan, digest office RKA)
  • v10.1 belum memuat 5 perbaikan terakhir saya (cakupan dokumen besar, mode fokus LKE, RKA office-suffix, dll.)
  • v10.1 menambahkan perbaikan teknis yang belum ada di sini (OCR, render LHP, tahapan sentinel-flag)

Kabar baik: tidak ada perubahan skema basis data — sehingga tidak perlu migrasi. Ini menghilangkan risiko terbesar merge.

2Temuan Utama: Temuan Deterministik Ditolak

⚠ Dugaan Anda benar — dan sudah terbukti

v10.1 memasukkan kembali mekanisme temuan deterministik yang bertentangan dengan doktrin baru: file prefill_temuan.py beserta dua tool build_draft_temuan_from_anomalies dan read_draft_temuan. Mekanisme ini mengubah anomalies-master.json menjadi temuan tanpa melibatkan AI.

Rantai bukti (4 langkah)

  1. run_batch_rka selalu mengirim argumen --digest-only.
  2. Di v6/scripts/reviu-rka-kl/run_batch.py:243, cross_check hanya berjalan if ok_tor and ok_rab and not digest_only → selalu dilewati.
  3. Pemindaian seluruh penugasan riil: nol berkas anomalies*.json.
  4. Doktrin eksplisit di anggota_tim.md: "Skill PBJ kini MODE FULL-AI — TANPA rule/anomali."

Kesimpulan: komponen tersebut bukan hanya bertentangan doktrin, tetapi juga kode mati — masukannya tidak pernah diproduksi pada alur full-AI.

✓ Keputusan & verifikasi

prefill_temuan.py tidak disalin ke repositori ini, dan kedua tool tidak didaftarkan. Diverifikasi otomatis: registry berisi 13 tool, nol tool deterministik, sementara write_penilaian_aspek (penilaian per-aspek) tetap ada.
